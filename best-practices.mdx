## Content Organization

Well-organized documentation is easier to navigate and maintain. Follow these guidelines for structuring your content.

<Columns cols={2}>
  <Card title="Logical Hierarchy" icon="layers" href="#hierarchy">
    Use clear headings and subsections to create logical flow.

  <Card title="Consistent Naming" icon="tag" href="#naming">

## Writing Guidelines

<Tabs>
  <Tab title="Style" icon="edit">
    Write in active voice, use present tense, and keep sentences concise.
    
    <Callout kind="tip">Use second-person language to address readers directly.</Callout>
  </Tab>
  <Tab title="Formatting" icon="type">
    Use headings, lists, and code blocks appropriately. Include examples and screenshots.
    
    <Expandable title="Code Examples" default-open="false">
      Always include practical code examples with realistic data. Avoid placeholders like `foo` or `bar`.
    </Expandable>
  </Tab>
</Tabs>

## Maintenance

Regular maintenance ensures your documentation stays current and useful.

<Steps>
  <Step title="Review Regularly" icon="eye">
    Schedule quarterly reviews of your documentation for accuracy.
  </Step>
  <Step title="Update Examples" icon="refresh-cw">
    Keep code examples and screenshots current with your latest changes.
  </Step>
  <Step title="Gather Feedback" icon="message-square">
    Collect user feedback through surveys or issue trackers.
  </Step>
</Steps>

## Common Pitfalls

<ExpandableGroup>
  <Expandable title="Avoid jargon without explanation" default-open="false">
    Define technical terms on first use. Don't assume readers know industry-specific acronyms.
  </Expandable>
  <Expandable title="Don't duplicate content" default-open="false">
    Use cross-references instead of copying information between pages.
  </Expandable>
</ExpandableGroup>
